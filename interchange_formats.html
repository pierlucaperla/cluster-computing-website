Dati diversi, un linguaggio comune

CSV, XML e JSON: tre modi per rappresentare e scambiare informazioni fra applicazioni.

Un formato di interscambio stabilisce come scrivere i dati perché programmi diversi possano interpretarli. Nei sistemi distribuiti, questo accordo permette di trasferire informazioni fra nodi, servizi e strumenti di analisi. Sintassi, significato dei campi e codifica devono essere condivisi: un file leggibile non garantisce da solo che due programmi lo interpretino allo stesso modo.

Gli esempi originali seguenti descrivono gli stessi due nodi di un cluster: identificativo, nome e numero di CPU. Cambia la rappresentazione, mentre le informazioni restano confrontabili.

CSV — Comma-Separated Values

CSV rappresenta una tabella testuale: ogni record contiene campi separati da virgole, con un’intestazione facoltativa. La RFC 4180, documento informativo, descrive una convenzione comune e il tipo MIME text/csv.

  • Caratteristiche: struttura piatta, sintassi essenziale e pochi caratteri aggiuntivi; utile per esportazioni da database, fogli di calcolo e risultati numerici.
  • Peculiarità: i campi contenenti virgole, doppi apici o ritorni a capo vanno racchiusi tra doppi apici; un apice interno si raddoppia. Tutti i record devono avere lo stesso numero di campi.
  • Limiti: non definisce tipi nativi o gerarchie. Separatore, codifica e interpretazione dei valori vuoti vanno concordati; alcune applicazioni usano varianti con punto e virgola.
id,nome,cpu
1,"Nodo, principale",16
2,Nodo di calcolo,32

Le virgolette proteggono la virgola nel primo nome. Il valore 16 diventa un numero solo se il programma che importa i dati lo interpreta come tale.

XML — eXtensible Markup Language

XML è un linguaggio di marcatura estensibile: tag scelti dall’autore descrivono elementi, attributi e relazioni gerarchiche. La specifica XML 1.0 del W3C ne definisce la sintassi.

  • Caratteristiche: un unico elemento radice, elementi correttamente annidati, nomi sensibili alle maiuscole e attributi con valori tra virgolette.
  • Peculiarità: può combinare testo ed elementi e includere commenti. Una DTD può definire la struttura ammessa: essere ben formato riguarda la sintassi, essere valido richiede anche il rispetto delle regole dichiarate.
  • Limiti e impieghi: i tag rendono esplicita la struttura, ma aumentano la verbosità. È adatto a documenti strutturati e scambi che richiedono regole formali.
<?xml version="1.0" encoding="UTF-8"?>
<cluster>
  <nodo id="1">
    <nome>Nodo, principale</nome>
    <cpu>16</cpu>
  </nodo>
  <nodo id="2">
    <nome>Nodo di calcolo</nome>
    <cpu>32</cpu>
  </nodo>
</cluster>

cluster è la radice; ogni nodo ha un attributo e due figli. Senza ulteriori regole, il contenuto di cpu è testo. Nei valori testuali, caratteri come < e & richiedono escape, rispettivamente &lt; e &amp;.

JSON — JavaScript Object Notation

JSON è un formato testuale per dati strutturati, indipendente dal linguaggio di programmazione nonostante il nome. La RFC 8259 ne specifica sintassi e interoperabilità.

  • Caratteristiche: oggetti con coppie nome-valore e array ordinati. I valori possono essere stringhe, numeri, booleani, null, oggetti o array.
  • Peculiarità: nomi e stringhe richiedono doppi apici; i nomi nello stesso oggetto dovrebbero essere unici. Gli scambi tra sistemi aperti richiedono UTF-8.
  • Limiti e impieghi: utile per messaggi di API e servizi distribuiti. La sintassi standard non ammette commenti, virgole finali o tipi data; le date richiedono una convenzione, per esempio una stringa concordata.
{
  "nodi": [
    { "id": 1, "nome": "Nodo, principale", "cpu": 16 },
    { "id": 2, "nome": "Nodo di calcolo", "cpu": 32 }
  ]
}

nodi contiene un array di oggetti. Qui cpu è un numero nativo; l’ordine degli elementi dell’array è significativo, quello delle proprietà di un oggetto non lo è.

Per scegliere: CSV semplifica uno scambio di righe e colonne; XML offre una rappresentazione documentale articolata; JSON esprime direttamente strutture di oggetti e liste. Nel contesto di un cluster, si può esportare una tabella di misure in CSV, descrivere un documento strutturato in XML o inviare lo stato dei nodi tramite JSON.

Nessuno dei tre è sempre migliore: dimensioni e tempi di elaborazione dipendono dal contenuto e dagli strumenti. Prima dello scambio occorre concordare nomi, unità di misura, campi obbligatori e gestione dei dati mancanti, oltre a verificare che il destinatario supporti il formato scelto.
